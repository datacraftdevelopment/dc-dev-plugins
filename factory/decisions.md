# Decisions

- 2026-10-05 · Start with a deterministic script as the manager, not an LLM manager. Management by script costs no tokens and is readable; PM's own pm-021 measured 2.6x usage when an orchestrator was the default. Hermes stays the LLM-manager comparison.
- 2026-10-05 · First experiment runs headless `claude -p` on the host in git worktrees, not Sandcastle in Docker. It removes container auth and Docker from the first test; Sandcastle is experiment 02 once the loop shape is proven.
- 2026-10-05 · Judgment is declared on the ticket at planning time (`Gate: human`) rather than discovered by the agent mid-run. Discovered blockers still park as `needs-human`.
- 2026-10-05 · Reuse pm's tracker format unchanged, adding only `Gate:` and `Branch:` header lines.
- 2026-10-05 · Approvals must land in the tracker, not arrive as relayed messages. The first real run showed the Mac's auto-mode check rejects a go relayed through another Claude session. Experiment 03 has a decision tap edit the ticket (or a Linear/GitHub status), and Runway picks it up on its schedule.
- 2026-10-05 · Linear is Runway's first real tracker, through an adapter (`linear_tracker.py`) behind the same ticket interface as markdown. Runway's queue is Matt's triage labels (`ready-for-agent` = auto, `ready-for-human` = gated), so `/to-tickets` output is runnable as published and Wayfinder decision tickets are ignored.
- 2026-10-05 · Joe's go is a Linear comment starting `go` (or a `go` label). It lands in the tracker, so no Claude session relays it; the note after `go` reaches the agent. Runway's own comments carry a marker so they're never mistaken for Joe's.
- 2026-10-05 · Runway authenticates to Linear with a personal API key in the macOS keychain, not the connector. A scheduled script can't use the connector's sign-in; the connector is for the planning skills.
- 2026-10-05 · The trigger is a launchd LaunchAgent on the Mac running `runway loop` every 10 minutes, with a lock so runs never overlap. A cloud routine can't reach the Mac's checkouts or toolchain.
- 2026-10-06 · Runway stays the engine; Matt's `/implement-spec` isn't adopted. It's started by hand, managed by an LLM, and has no human gates, so it doesn't touch the trigger bottleneck. Runway borrows its whole-branch review instead (`research/06`).
- 2026-10-06 · Runway ends each build with a finish step: review against the tickets, one fix pass kept only if the check passes, and a `/pr`-shaped body. The PR is written to a file by default; pushing and opening a draft PR is opt-in per repo (`"pr": "draft"`) because it's an outside action.
- 2026-10-06 · Every agent call is logged with its session id and tokens, and `runway retro` feeds the struggling runs to `/retro`. That's the factory's learning loop, with retries and parks per ticket as the metric.
- 2026-10-06 · Matt's v1.3 video ranks a deterministic loop above sub-agent orchestration as more reliable and cheaper, which backs Runway as the engine (`research/07`). No change.
- 2026-10-06 · `/retro` stays human-started: `runway retro` only writes a prompt, is never scheduled, and nothing it proposes lands without Joe picking it. Matt warns an automated retro loops on its own false positives.
- 2026-10-06 · `runway retro` should also send a small random sample of clean runs, not only the ones that struggled, and point `/retro` at Runway's own prompts so instruction no-ops in the factory get caught. Pending code change, after the move into `dc-dev-plugins/factory`.
- 2026-10-08 · Runway's workers in this repo are pinned to `claude-sonnet-5-5` (agent, prep and review commands; the fix pass and PR body inherit them). The exact ID, not the `sonnet` alias, so a new Sonnet is a deliberate switch rather than a surprise. A `harness:opus` label runs one ticket on `claude-opus-5-5`. Why: every agent session so far ran on Sonnet 5.5 only by CLI default, and all 23 tickets of 10-07 passed their checks; Opus 5.5 costs twice as much per token. The template and skill follow in DAT-43.
- 2026-10-08 · The app's side panel reads as a timeline: the queue above (nearest ticket just over Now), the running tick in the middle, finished tickets below, newest first, merged across projects and split by day. A ticket logged done whose calls used no tokens is shown as "agent never ran", folded with its neighbours, never as done: DAT-35 to DAT-39 were logged that way on 2026-10-08.
- 2026-10-08 · Pointing a repo at GitHub is one documented path like Linear's: `setup.sh <repo> --github [owner/name]` writes the tracker doc (Matt's GitHub conventions unchanged, plus Runway's labels and gating rule) and a `runway.json`; `runway setup` checks auth, repo and Issues, creates only missing labels (never recolors) and warns when the repo is public. Why: a public repo makes every packet and comment public, so the warning belongs at setup, not after the first run. Factory 0.5.0.
- 2026-10-09 · The RCC and TC editions follow pm 0.25.0: one pm in every edition, no separate `sdlc` plugin cut back out (GitHub #6). Why: one plugin shape everywhere, with no split rule to maintain on every pm change. Cost: students reinstall pm once and remove the old `sdlc` plugin so they don't carry two credential guards. The edition scripts hold no `sdlc` entries; `portable-overlay/README.md` has the hand-pass steps. Joe runs the cuts and any push to the public RCC repo, after #5 is on `main`.
- 2026-10-09 · Runway can merge: with `"merge": "on_pass"`, a `pass` verdict with no hold merges the integration branch into base at exactly the reviewed SHA (`"pr": "draft"`: `gh pr ready`, then `gh pr merge --merge --match-head-commit <sha>`; `"pr": "file"`: `git merge --no-ff <sha>` in a throwaway worktree on base, then push). A moved head, a conflict or a refused push merges nothing and is logged; the PR waits for the next finish. A hold (one-way door, or a ticket gated for a human) never merges in any mode, and the PR says "Held for Joe: <reason>". `shadow` only writes "would merge <sha>". Why: the review proves one SHA, so the merge is pinned to it, not to whatever the branch became. This repo stays on `shadow` until Joe switches it after watching a few rounds (GitHub #32, part of #27).
